# 요구사항 명세

## 시나리오 (가정)

가상의 지역은행 **B은행**은 인터넷뱅킹 웹 서버와 직원용 업무 시스템(관리자 페이지)을 운영한다.
2026년 하반기 금융권에서 AI 자동화 공격, 직원용 시스템 침입, 본인 확인 우회를 통한 개인정보 유출이 잇따르자,
네트워크 침입 탐지 체계가 아래 요구사항을 만족하는지 검증하기로 했다.

- 지키려는 것: 고객 거래정보, 직원용 업무 시스템
- 참고한 실제 사례(보도 기준): 신한은행 본인 확인 절차 우회, KB국민은행 직원용 모바일 업무지원 시스템 공격, 금융감독원의 AI 에이전트 추정 공격 IP 특정, 크레덴셜 스터핑 증가
- 은행 이름은 가상으로 처리했다. 실제 은행 시스템을 점검한 것처럼 보이지 않게 하기 위함이다.

## 요구사항 (확정본)

| ID | 요구사항 | 합격 기준 | 근거 | 상태 |
|---|---|---|---|---|
| REQ-01 | 관리자 페이지 접근 시도를 탐지한다 | `/admin` 및 하위 경로 요청 시 대소문자·URL 인코딩 등 표기 방식과 무관하게 경보 | 직원용 시스템 공격 사례 | 테스트 완료, **DEF-001** |
| REQ-02 | 관리자 페이지와 무관한 정상 요청은 탐지하지 않는다 | 주소에 admin 글자가 있어도 관리자 경로가 아니면 경보 없음 | 오탐은 IPS 차단 시 고객 피해 | 테스트 완료, **DEF-002** |
| REQ-03 | 자동화 스캐닝을 탐지한다 | 같은 출발지에서 10초 안에 존재하지 않는 페이지 요청이 20회 이상이면 경보 | AI 에이전트의 동시다발 탐색 | 미착수 |
| REQ-04 | 반복 로그인 시도를 탐지한다 | 같은 출발지에서 60초 안에 로그인 요청이 5회 이상이면 경보 | 크레덴셜 스터핑 | 미착수 |
| REQ-05 | 위협 IP의 접근을 탐지한다 | 위협 IP 목록의 출발지 접근 시 경보, 목록 외 IP는 경보 없음 | 금감원 공격 IP 특정 | 미착수 |
| REQ-06 | 민감정보 유출을 탐지한다 | 서버 응답에 주민등록번호 형식(6자리-7자리) 데이터가 포함되면 경보 | 개인정보 유출 사고 | 미착수 |

> REQ-04·05·06 테스트에는 로그인 페이지, 두 번째 출발지 IP, 가짜 개인정보가 담긴 테스트 페이지가 필요하다.
> 모두 실습 환경 안에서 **가짜 데이터**로만 구성한다.

## 기준값 설정 근거

| REQ | 기준 | 근거 |
|---|---|---|
| REQ-03 | 10초 안에 없는 페이지 20회 | 사람이 없는 페이지를 누르는 건 많아야 몇 번. 초당 2회로 20번이면 프로그램 속도로 판단 |
| REQ-04 | 60초 안에 로그인 5회 | 금융 서비스는 흔히 비밀번호 오류를 5회 안팎으로 제한. 1분 안에 5번은 계정 잠김 직전 수준의 이상 시도로 판단 |

기준값은 오탐과 미탐의 균형을 고려해 설정했으며, 실제 운영 시에는 트래픽 데이터를 기반으로 조정이 필요하다.

## 기대 결과를 정하는 원칙

기대 결과는 **룰 문장이 아니라 룰의 목적(요구사항)과 사용자 의도** 기준으로 정한다.
"룰에 nocase가 없으니 안 잡히는 게 정상"이 아니라 "대문자로 쳐도 관리자 페이지 접근 시도이므로 잡혀야 한다"가 기대 결과다.
기대와 실제가 다르면 그것이 결함이다.

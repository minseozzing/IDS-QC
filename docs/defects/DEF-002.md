# DEF-002: 관리자 페이지가 아닌 요청(/admin2, /blog/admin-tips)에 관리자 접근 경보 오발생

| 항목 | 내용 |
|---|---|
| 유형 | 오탐 |
| 심각도 | **Minor** (IPS 차단 모드 운영 시 Major로 상향) |
| 위반 요구사항 | REQ-02 (관리자 경로가 아니면 경보 없음) |
| 관련 TC | TC-002-08, TC-002-09 |
| 대상 룰 | sid 1000002 (TEST Admin Access), rev 1 |
| 환경 | Ubuntu 22.04.5, Suricata 8.0.8, IDS 모드 |

## 재현 절차

1. Suricata 실행 상태 확인
2. `curl.exe --path-as-is http://192.168.56.10/blog/admin-tips` 요청
3. `curl.exe --path-as-is http://192.168.56.10/admin2` 요청
4. `eve.json`의 http·alert 이벤트를 출발지 포트로 대조

## 기대 결과

두 요청 모두 경보 없음

## 실제 결과

두 요청 모두 sid 1000002 경보 발생 (출발지 포트 5819, 5022)

## 원인 (분석)

룰이 주소 안에 `/admin` 글자가 **어디든** 포함되면 경보를 울린다. `/admin` 경로 자체인지, 뒤에 다른 글자가 붙은 다른 경로인지 구분하지 않는다. (경계 검사 없음)

## 영향

- 관리자 페이지 접근 의도가 없는 정상 고객 요청에도 경보가 발생한다.
- **IPS 차단 모드**라면 블로그 글을 읽으려던 고객이 차단되어 정상 서비스를 이용하지 못한다.
- IDS 모드에서도 불필요한 경보가 쌓여 관제 담당자가 실제 공격을 놓칠 위험이 커진다.

## 심각도 판단 근거

IDS 모드에서는 경보가 남아 사람이 걸러낼 수 있으므로 Minor. 다만 차단 장비(IPS)로 운영하면 업무 영향이 생기므로 Major로 상향한다.

## 조치 계획

`/admin` 뒤에 경계를 요구하도록 룰 수정 (rev 2). 예: 경로 끝 또는 `/`, `?` 앞에서만 매칭. 수정 후 TC-002-08, 09 재테스트 및 TC-002-01·02·07 회귀 확인.

# DEF-001: 대문자 경로(/ADMIN) 요청 시 관리자 페이지 접근 탐지 실패

| 항목 | 내용 |
|---|---|
| 유형 | 미탐 |
| 심각도 | **Major** |
| 위반 요구사항 | REQ-01 (표기 방식과 무관하게 관리자 경로 접근 탐지) |
| 관련 TC | TC-002-03 |
| 대상 룰 | sid 1000002 (TEST Admin Access), rev 1 |
| 환경 | Ubuntu 22.04.5, Suricata 8.0.8, IDS 모드 |
| 상태 | **해결 확인** (rule rev2, 2026-11-08 회귀 테스트) |

## 재현 절차

1. Suricata 실행 상태 확인
2. `curl.exe --path-as-is http://192.168.56.10/ADMIN` 요청
3. `fast.log` 및 `eve.json` 확인 (http 이벤트와 alert 이벤트를 출발지 포트로 대조)

## 기대 결과

sid 1000002 경보 1건 발생

## 실제 결과

경보 없음. `eve.json`의 http 이벤트에는 요청이 기록됨(src_port 5815) → **트래픽은 수신했으나 탐지만 실패**.

## 원인 (분석)

룰의 `content:"/admin"` 매칭이 대소문자를 구분한다. (`nocase` 옵션 없음)

## 영향

공격자가 경로를 대문자로 바꾸는 것만으로 탐지를 우회할 수 있다. 경보가 남지 않으므로 공격이 있었다는 사실 자체를 아무도 알 수 없다.

## 심각도 판단 근거

미탐은 **볼 수조차 없다**. 오탐은 관제 요원이 경보를 보고 걸러낼 수 있지만 미탐은 기록이 남지 않는다. 대문자 변경이라는 쉬운 방법으로 우회되므로 Major로 판단했다.

## 조치 및 해결 확인

- 조치: 룰에 `nocase` 추가 (rev 2, DEF-002 수정과 함께 `startswith`, `pcre` 경계도 적용)
  - rev1: `content:"/admin";`
  - rev2: `content:"/admin"; nocase; startswith; pcre:"/^\/admin(?:[\/?]|$)/i";`
- 재테스트 (2026-11-08): TC-002-03 `/ADMIN` 요청(출발지 포트 1821)에서 rev2 경보 발생 → **Pass**
- 회귀: 기존 Pass였던 TC 7개 모두 유지, 전체 TC 10개 Pass 10 / Fail 0 ([docs/03-test-cases.md](../03-test-cases.md))
